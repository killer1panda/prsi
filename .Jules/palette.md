## 2024-08-28 - Async Analysis Feedback and Accessibility
**Learning:** For asynchronous tasks like model predictions, simple visual feedback (e.g., text changes) is often insufficient for screen readers without `aria-live` properties. Further, `textarea` inputs that lack an associated `<label>` (relying purely on `placeholder`) create major barriers for screen reader users and those navigating by keyboard. Disabled buttons also need specific visual styling to communicate non-interactivity, as well as focus states for navigation.
**Action:** When creating async analysis forms, always provide an associated `<label>` for text areas, include `aria-live="polite"` on output regions (including the loading button/text), and ensure button `:disabled` and `:focus-visible` CSS states are defined.
