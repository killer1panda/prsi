## 2025-03-07 - Optimization in temporal edge extraction nested loop
**Learning:** In Neo4j graph production builds (`extract_temporal_edges`), calculating user interactions within a timeframe used an $O(N^2)$ nested loop despite the users list already being sorted by timestamp. This is a common anti-pattern in temporal aggregations.
**Action:** Always check if loops iterating over sorted data (like timestamps) can be short-circuited with an early `break` condition (e.g., breaking once the `time_diff` exceeds the window) to reduce the algorithm's actual time complexity.
## 2023-10-25 - React Component Polling Performance
**Learning:** Polling logic built into parent components (e.g., using `setInterval` or `useEffect` loops) cascades updates deeply into non-state-dependent child functional components. Simply using Next.js doesn't prevent standard React render pollution. Also, fixing linter errors related to synchronous state updates within a `useEffect` (like calling `setState` immediately on mount) by lifting the initial state directly into the `useState` hook prevents a double render cycle at initialization.
**Action:** When a parent component implements frequent polling intervals or global event streams, identify pure display child components (like data panels or forms) and proactively wrap them in `React.memo()`. Ensure `.displayName` is attached to wrapped functional components to satisfy linters and maintain DevTools readability. Initialize state variables with their actual starting condition in `useState` instead of overriding them synchronously in `useEffect`.
