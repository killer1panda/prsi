## 2024-11-20 - Hardcoded Production Credentials in Multiple Contexts
**Vulnerability:** A hardcoded production password (`doom_index_prod_2026`) for Neo4j was found explicitly in the source code (`src/data/populate_neo4j_production.py`), CI/CD workflows (`.github/workflows/ci.yml`), integration tests (`tests/comprehensive/test_production.py`), and documentation (`EXECUTION_SUMMARY.md`).
**Learning:** Hardcoded credentials can easily spread from initial source files into test environments, GitHub Actions configs, and documentation as developers copy-paste configurations to make setups work seamlessly. This creates a multi-vector exposure risk, especially in public repositories or when code is shared across different teams, and bypasses expected environment variable behavior.
**Prevention:** Always rely strictly on environment variables (`os.getenv`) without hardcoded fallback credentials in source files. For tests and CI/CD pipelines, use explicit test/mock credentials (e.g., `test_password`). Avoid placing actual or fallback passwords in documentation; instead, use placeholders like `YOUR_PASSWORD_HERE`. Employ tools like `gitleaks` in pre-commit hooks to catch these patterns before they are committed.
