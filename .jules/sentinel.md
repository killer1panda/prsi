## 2026-08-17 - [Hardcoded Neo4j Password in Production Config]\n**Vulnerability:** A hardcoded production password ('doom_index_prod_2026') is used in multiple files, including `src/data/populate_neo4j_production.py`, tests, and GitHub Actions workflows, exposing the database to unauthorized access.\n**Learning:** Hardcoded credentials are a critical vulnerability and can easily spread throughout a codebase via configuration files and scripts. Always rely on secure environment variables or secrets management solutions instead of hardcoding sensitive defaults, especially for production environments.\n**Prevention:** Use `os.getenv` or similar mechanisms to fetch sensitive values at runtime. For CLI tools, provide them as arguments or require them in environment variables, without falling back to a hardcoded sensitive string. Adopt secret scanning tools in CI/CD pipelines to catch accidental commits of secrets.
